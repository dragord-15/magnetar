# 12 — ملاحظات وقيود اللغة الحالية

> **TL;DR**
> - ما هو **مكتمل**: التحليل اللغوي، الأنواع، التحكم، الدوال، البنى، المؤشرات، الوحدات، والمدمجة.
> - ما هو **قيد الإكمال**: `arm64`، `riscv`، الأنواع التركيبية، وبعض الدوال المدمجة.
> - ما هو **غير مدعوم**: `baremetal`، صيغ `asm`/`bin`، namespaces، و Windows/macOS.
> - القيود العملية التي تفاجئك: الطبع بلا سطر جديد، طباعة الكسور بلا حشو أصفار، وغياب فحص الحدود.
> - خارطة التطوير ومراحلها، والمواضيع غير الموثّقة بعد، في نهاية الفصل.

**حالة الدعم:** ✅ مستقر (مرجع القيود نفسه)

هذا الفصل يوضّح بحالتها الراهنة (v3.5) ما هو **مكتمل**، وما هو **قيد الإكمال**، وما هو
**غير مدعوم بعد**، بناءً على قراءة الكود في `src/` وتحقّق عملي من سلوك المترجم.

---

## المكتمل والمستقر

- ✅ التحليل اللغوي والنحوي (Lexer + Parser) لكل البنى الأساسية.
- ✅ المتغيرات (`let` بكل صيغه + الأسلوب الكلاسيكي).
- ✅ أنواع: `int` (64-bit)، `float`، `bool`، `char`، `string`.
- ✅ العمليات الحسابية/المنطقية/البتية + الإسناد المركّب + `++`/`--` + `?:`.
- ✅ التحكم: `if/else`, `while`, `do-while`, `for`, `range for`, `switch`, `match`, `goto`, `break`, `continue`.
- ✅ الدوال + الاستدعاء الذاتي + تمرير البنى بالقيمة والمؤشرات.
- ✅ البنى (`struct`) والتعدادات (`enum`).
- ✅ المؤشرات (بما فيها `**`) والمصفوفات (`fixed<T,N>`, `dyn<T>`) والمصفوفات متعددة الأبعاد بنمط C (`int a[2][3]`, `fixed<fixed<T,M>,N>`) و `alloc<T>(n)` و `new`/`free` و `sizeof`.
- ✅ `dyn<T>` بعمليات `push/pop/len/clear`، و`range` كقيمة عامة (`start/end/step`)، و`raw<T>`، و`typeof`.
- ✅ `const` يمنع الإسناد و`++`/`--` والإسناد المركّب وقت التصريف.
- ✅ `half` يُعامل كـ `float` 32-بت (وليس IEEE نصف دقة)، و`nan`/`inf` قابلان للطباعة مباشرة.
- ✅ الوحدات عبر `use` (تضمين نصّي) + مسارات مكتبات متعددة.
- ✅ أكثر من 120 دالة مدمجة (150 اسماً في المجموع، منها 112 من نوع `sys_*`)، أهمها syscalls Linux.
- ✅ الطبع لكل الأنواع الأساسية (بدون سطر جديد).
- ✅ Backend `x86_64` ينتج ELF مستقل يعمل بلا libc.
- ✅ وضع المراقبة الحيّ (`--watch`).
- ✅ CLI منظّم مع `--help` ورسائل أخطاء واضحة.

---

## قيد الإكمال

- ⚠️ **Backend `arm64`** — الواجهة موجودة في `src/backend/arm64/backend.c`، لكن قد لا
  تغطي كل الأنماط. يحتاج اختباراً موسّعاً.
- ⚠️ **Backend `riscv`** — مثل arm64: موجود لكن غير مُختبر بشكل كافٍ.
- ⚠️ **بعض الأنواع التركيبية** — `class`, `interface`, `trait`, `union` معرّفة في النحو
  (`token.h` / `ast.h`) لكن دعمها الدلالي/التوليدي قد يكون جزئياً.
- ⚠️ **`export` و `module`** — معرّفة ككلمات لكن النظام يعتمد أساساً على `use` كتضمين.
- ⚠️ **بعض الدوال المدمجة المتقدمة** (مثل الصوت `audio_play`، قاعدة البيانات `sql_*`،
  `crypto_*`، `regex_match`) — موجودة كواجهات؛ قد تكون مبسّطة/جزئية.

---

## غير مدعوم بعد

- ❌ **هدف Baremetal** — صريح في `main.c`:
  ```
  --target=baremetal is not implemented yet.
  ```
- ❌ **صيغة ASM (`.s`)** — مخطط لها لكن غير منفّذة (`--format=asm`).
- ❌ **صيغة Binary خام (`.bin`)** — مخطط لها لكن غير منفّذة (`--format=bin`).
- ❌ **دعم Windows (PE) و macOS (Mach-O)** — الخرج حالياً ELF فقط.
- ❌ **نظام وحدات معزول بنطاقات (namespaces)** — `use` تضمين نصّي فقط.
- ❌ **نظام أخطاء دلالية عميق** — التحقق من الأنواع جزئي.
- ❌ **فحص حدود المصفوفات** — لا `bounds checking` إطلاقاً.

## قيود يجب الانتباه لها عند الكتابة

### 1) الطبع لا يضيف سطراً جديداً

```c
print("hello");       // لا سطر جديد
print("hello\n");     // أضف \n يدوياً
```

### 2) طباعة الأعداد العشرية ليست 4 منازل دائماً

القاعدة الفعلية في v3.5: يُطبع **الجزء الصحيح** (مقطوعاً نحو الصفر)، ثم نقطة، ثم
**الكسور كعدد صحيح** يساوي `trunc(الكسور × 10000)` — أي **أربعة منازل كحد أقصى
وبلا حشو أصفار**:

```c
print(3.5);      // 3.5000   (4 منازل لأن الكسور = 0.5)
print(2.25);     // 2.2500
print(0.05);     // 0.500    (3 منازل فقط — بلا حشو أصفار)
print(1024.0);   // 1024.0   (بلا كسور فلا منازل إضافية)
print(10.0/3.0); // 3.3333
```

> ⚠️ **دقّة `float` (32-bit) تُظهر نفسها:** القيمة `3.1` تُخزَّن كـ `3.0999999...`،
> فيُقطع الكسور إلى `999` فتُطبع `3.999` بدل `3.1`، وبالمثل `2.1` تُطبع `2.999`.
> إن كانت الدقة مهمّة، اعمل على `int` (مضاعفات 1000 مثلاً).

> ⚠️ **الأعداد العشرية السالبة مكسورة في v3.5:** `print(-3.5)` يطبع البتات
> الخام للقيمة (`-1080033280`)، و `float x = -3.5;` يفقد إشارته (تصير `x = 3.5`).
> اعمل على `int` إن كانت القيم السالبة شائعة.

### 3) قسمة الأعداد الصحيحة تُهمل الكسور

```c
print(10 / 3);   // 3  وليس 3.3333
```

### 4) المقارنات ترجع 1/0

```c
print(3 < 5);    // 1
print(3 == 5);   // 0
```

> أما متغيّر من نوع `bool` فيُطبع `true`/`false`، لا `1`/`0`:

> ```c
> bool b = true;
> print(b);      // true
> ```

### 5) `alloc<T>(n)` تُفهرَس يدوياً بالبايت

`n` في `alloc<T>(n)` هو **عدد العناصر**، لا عدد البايتات. ولأن المؤشر لا يملك
معامل `[]`، تكون الفهرسة يدوية بالبايت:

```c
int* b = alloc<int>(3);
*(b + 0 * sizeof(int)) = 1;
*(b + 1 * sizeof(int)) = 2;
*(b + 2 * sizeof(int)) = 3;
```

القواعد الكاملة وجدول الإزاحة لكل نوع في
[المرجع الموحّد: alloc<T>(n)](07_pointers_arrays_memory.md#المرجع-الموحّد-alloctn).

### 6) ترتيب تعريف الدوال لا يهم

**الترتيب لا يهم**؛ والسبب الحقيقي لخطأ `Undefined symbol` هو أن الرمز **غير معرَّف** أصلاً.
داخل **نفس الملف** يمكنك استدعاء دالة معرَّفة **بعد** نقطة الاستدعاء (بما فيها بعد `main`):
المترجم يجمع الرموز أولاً ثم يولّد الشيفرة، فلا علاقة للترتيب بالربط.

```c
fn main() { helper(); }        // ✅ يعمل
fn helper() { print("hi\n"); } // معرَّفة لاحقاً
```

`error: Undefined symbol 'name'` يعني أن **الرمز غير موجود**، لا أنه معرَّف في مكان خاطئ.
الأسباب العملية الثلاثة:

| السبب | المثال | الحل |
|-------|--------|------|
| دالة مدمجة بلا تصريح | `sqrt(2.0)` | `extern fn sqrt(float) -> float;` (البند 7) |
| اسم دالة غير موجود (خطأ مطبعي) | `nosuchfn(1)` | صحّح الاسم |
| استدعاء دالة عضو (method) باسمها المجرّد | `magnitude()` | `this.magnitude()` |

> ويشمل ذلك **استدعاء دالة عضو داخل بنية أو صنف**: لا تستدعِها باسمها فقط، بل عبر `this.<اسم>`:
>
> ```c
> class Vector3 {
>     float x; float y; float z;
>     fn magnitude() -> float { return sqrt(x*x + y*y + z*z); }
>     fn normalize() -> void {
>         float mag = this.magnitude();   // ✅
>         // float mag = magnitude();     // ❌ Undefined symbol 'magnitude'
>     }
> }
> ```
>
> رسالة الخطأ نفسها تظهر عند تشغيل الأمثلة الجاهزة في `examples/` (انظر «كيف تتحقق من الاستقرار بنفسك» أدناه).

### 7) الدوال المدمجة تحتاج تصريحاً

`print` و `len` وحدهما تعملان بلا تصريح. أمّا بقية الدوال المدمجة — بما فيها
`sqrt` و `sys_open` — فتحتاج سطر `extern fn` في أعلى الملف، وإلا فشل الترجمة
بـ `Undefined symbol`. راجع [09_builtins.md](09_builtins.md).

### 8) `use` يتطلب موقعاً صحيحاً للملف

يجب أن يكون المجلد `lib/` بجانب الملف الحالي، أو أن تكون الوحدة في نفس المجلد.
وعمق التداخل محدود بـ **32**، وعدد الوحدات المحمّلة بـ **64** — راجع
[08_modules.md](08_modules.md#حدود-use-والآثار-الجانبية).

### 9) الدوال المدمجة محجوزة

لا تُعرّف دوال بأسماء مثل: `print`, `len`, `alloc`, `new`, `free`, `exit`, `sizeof`, ...

## خريطة التطوير (المراحل المنتهية والمخططة)

المراحل 0 و 1 منتهيتان بالفعل؛ المراحل 2 وما بعدها مخططة.

| المرحلة | المهمة | الصعوبة | الحالة |
|---------|--------|---------|--------|
| 0 | التحقق من الأمثلة والاختبارات | سهل جداً | ✅ منتهية |
| 1 | تنظيف CLI ومعالجة الأعلام غير المنفّذة | سهل | ✅ منتهية |
| 2 | دعم إخراج Assembly (`.s`) | سهل → متوسط | ⏳ مخطط لها |
| 3 | دعم إخراج Binary خام (`.bin`) | متوسط | ⏳ مخطط لها |
| 4 | دعم Baremetal | صعب | ⏳ مخطط لها |
| 5 | إكمال Backend ARM64 | صعب | ⏳ مخطط لها |
| 6 | إكمال Backend RISC-V | أصعب | ⏳ مخطط لها |
| 7 | تحسين حالات الحافة والاستقرار | أصعب (مستمر) | ⏳ مخطط لها |
| — | دعم Windows (PE) / macOS (Mach-O) | متوسط → صعب | ⏳ مخطط لها |

## مواضيع غير موثّقة بعد

هذه المواضيع موجودة في اللغة أو في كود المترجم، لكنها **غير موثّقة** في هذا
الفصل (أو في أي فصل آخر). راجع الكود مباشرة إن احتجتها:

| الموضوع | الحالة | ملاحظة |
|---------|--------|--------|
| تحويلات الأنواع (casting) | غير موثّق | لا يوجد `as` ولا `int(x)` — الإسناد بين الأنواع لا يُفحص |
| نطاق المتغيرات (scope) | غير موثّق | القواعد الأساسية مفهومة (دالة/كتلة)، لكن التفاصيل الدقيقة غير موثّقة |
| حدود المصفوفات (bounds) | غير موثّق | افترض عدم وجود فحص — الفهرسة خارج النطاق سلوك غير معرّف |
| معالجة الأخطاء | غير موجود | لا `try/catch` ولا `?` — الفشل يُنتج رسالة ترجمة أو انهياراً |
| class/interface/trait | غير موثّق | معرّفة في النحو فقط |

## كيف تتحقق من الاستقرار بنفسك

مجموعة اختبارات الانحدار تُشغّل مباشرةً من جذر المشروع:

```bash
make
./tests/run.sh
```

ولترجمة الأمثلة يدوياً:

```bash
for f in examples/*.mg; do
    ./magc "$f" -o "/tmp/$(basename "$f" .mg)" && echo "OK   $f" || echo "FAIL $f"
done
```

الاختبارات تغطي نطاق الكتل و`sizeof` للمصفوفات الثابتة والمتعددة الأبعاد،
تهيئة `let fixed<T,N>` والمصفوفات `int a[2][3]` وحقول البنى متعددة الأبعاد،
حلقات `do-while` طويلة، القسمة الصحيحة على صفر، طباعة char كقيمة عددية، واستدعاء
method شقيقة. اختبار الحلقات المتداخلة يطبع `L` مرة واحدة لأن الطباعة تقع في
أعمق حلقة فقط.
