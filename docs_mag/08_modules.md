# 08 — الوحدات ونظام `use`

> **TL;DR**
> - `use "name";` **تضمين نصّي** في المعالجة المسبقة — لا استيراد معزول ولا namespaces.
> - يبحث الاسم العاري في `lib/` بجانب الملف المستورِد أولاً؛ والمسارات المكتوبة
>   تُحل نسبةً إلى الملف المستورِد قبل مسارات البيئة والنظام.
> - الامتدادان `.mg` و`.fc` مدعومان، والملفات المتداخلة تُحل نسبةً إلى المستورِد.
> - الوحدة المفقودة أو المجلد بدل الملف يوقف الترجمة برسالة خطأ.
> - كل ملف فعلي يُضمّن مرة واحدة: الحد الأقصى **64 وحدة** وعمق التداخل **32**.
> - تعارض الأسماء: **التعريف الأول يفوز** بصمت — لا يوجد خطأ redefinition.
> - حدود `use` وآثاره الجانبية موثّقة في [حدود use والآثار الجانبية](#حدود-use-والآثار-الجانبية).

**حالة الدعم:** ⚠️ جزئي (تضمين نصّي فقط)

## الفكرة

اللغة تدعم تضمين كود من ملفات أخرى عبر `use`. هذا يعمل كـ **تضمين نصي في مرحلة المعالجة
المسبقة** (preprocessing)، حيث يُدمج محتوى الوحدة داخل الملف الحالي قبل الترجمة.

## الصيغة

```c
use "mathx";
```

أو بدون علامات اقتباس:

```c
use mathx;
```

- الاسم العاري مثل `use "mathx";` يبحث في `lib/mathx.mg` بجانب الملف المستورِد،
  ثم في `mathx.mg` بجانبه، قبل الرجوع إلى المكتبات العامة.
- يمكن كتابة مسار مثل `use "./lib/mathx.mg";` أو `use "../shared/mathx";`.
- عند عدم كتابة امتداد، يجرب المترجم الملف كما كُتب ثم `.mg` ثم `.fc`.
- يجب أن يبدأ سطر `use` في أول السطر (يُسمح بمسافات بادئة)، وينتهي بفاصلة منقوطة.

## مثال عملي

**الملف `lib/mathx.mg`:**

```c
fn triple(int n) -> int {
    return n * 3;
}
```

**الملف `main.mg`:**

```c
use "mathx";

fn main() {
    print(triple(7));
    print("\n");
}
```

**الترجمة والتشغيل:**

```bash
./magc main.mg -o main
./main
# الناتج: 21
```

> **مهم:** يجب أن يكون الملف `main.mg` بجانب مجلد `lib/`، أو أن يكون `mathx.mg` في نفس
> مجلد `main.mg`.

## ترتيب البحث عن الوحدات

يبحث المترجم عن الوحدة بالترتيب التالي:

```
1. `<مجلد الملف المستورِد>/lib/<name>` (للأسماء العارية)
2. `<مجلد الملف المستورِد>/<المسار المكتوب>`
3. المسار المكتوب نسبةً إلى مجلد تشغيل المترجم، ثم `lib/<name>` (للأسماء العارية)
4. متغيّر البيئة: MAGNETAR_LIB ثم MAGNETAR_PATH ثم MAGNETAR_HOME
   (يُستعمل **واحد فقط** — أول متغيّر موجود في البيئة)
5. مسارات النظام:
     Linux:  /lib/magnetar/lib, /usr/local/lib/magnetar/lib, /usr/lib/magnetar/lib,
             /usr/share/magnetar/lib, /usr/local/share/magnetar/lib,
             /usr/local/lib/magnetar, /usr/lib/magnetar
     macOS:  /opt/homebrew/lib/magnetar, /usr/local/lib/magnetar, /Library/Magnetar/lib
     Windows: C:\Program Files\Magnetar\lib, C:\Magnetar\lib
6. `$HOME/.magnetar/lib/<name>`
7. `%LOCALAPPDATA%/Magnetar/lib` أو `%USERPROFILE%/.magnetar/lib` (ويندوز)
```

> **ملاحظة دقيقة:** لا تُفحص المتغيّرات الثلاثة كلها معاً؛ يفحص المترجم `MAGNETAR_LIB`
> أولاً، فإن لم يكن موجوداً انتقل إلى `MAGNETAR_PATH`، ثم `MAGNETAR_HOME`، ثم يتوقف.
> فإذا كان `MAGNETAR_LIB` معرّفاً على مسار خاطئ، فلن يُبحث في `MAGNETAR_PATH`.

## متغيّرات البيئة

| المتغير | الاستخدام |
|---------|-----------|
| `MAGNETAR_LIB` | مجلد المكتبات الأساسي |
| `MAGNETAR_PATH` | مسار إضافي للبحث (يُستعمل فقط إن لم يُعرَّف `MAGNETAR_LIB`) |
| `MAGNETAR_HOME` | مجلد تثبيت Magnetar (يُستعمل فقط إن لم يُعرَّف الاثنان السابقين) |

مثال:

```bash
export MAGNETAR_LIB=/opt/mylibs
./magc main.mg -o main
```

## منع التضمين المكرّر

- المترجم يتتبّع المسار الحقيقي للملف ويمنع تضمينه مرة أخرى حتى لو استُخدمت له
  صيغتا مسار مختلفتان.
- الحد الأقصى **64 ملفًا**؛ تجاوزه يوقف المعالجة برسالة خطأ.
- الملف المفقود أو المسار الذي يشير إلى مجلد يوقف الترجمة برسالة على `stderr`:

```
Error: Could not resolve use module 'mathx' from '...'
Error: Module preprocessing failed for 'main.mg'
```

## **طبيعة `use`**

- `use` هو **تضمين نصّي**، وليس نظام استيراد معزول: كل الرموز تصبح في نفس النطاق.
- لا توجد `namespace` أو فصل نطاقات فعلي حاليّاً.
- يمكن أن تحتوي الوحدة على دوال، بنى، تعدادات، إلخ.

## حدود use والآثار الجانبية

نظام `use` في v3.5 بسيط جداً: هو **نسخ نصّي** قبل الترجمة. وله حدود سلوكية
يجب أن تعرفها قبل أن تعتمد عليه.

### 1) Namespace غير موجود: كل الرموز في نطاق واحد

كل ما تعرّفه الوحدة يصبح مرئياً في الملف المستورِد كما لو كُتب فيه. لا يوجد
`namespace`، ولا `import` انتقائي، ولا `export` فعّال.

```c
// lib/mathx.mg
fn triple(int n) -> int { return n * 3; }
int PI = 3;              // متغيّر عام أيضاً!
```

الملف المستورِد يرى `triple` و `PI` معاً، وإن سمّى متغيّراً له نفس الاسم فسيتعارضان.

### 2) تعارض الأسماء: **التعريف الأول يفوز + تحذير**

لا يُصدر المترجم **خطأ** `redefinition` (للتوافق الخلفي)، لكنه يُصدر تحذيراً
واضحاً على `stderr` عند كل اسم مكرَّر في النص المدمج. أول تعريف يظهر في النص
النهائي هو الذي يُنفَّذ، والبقية مهملة.

**مثال يوضّح الخطر:**

```c
// lib/a.mg
fn helper() { print("from A\n"); }
```

```c
// lib/b.mg
fn helper() { print("from B\n"); }
```

```c
// main.mg
use "a";
use "b";
fn main() { helper(); }
```

الناتج:

```text
from A
```

أي أن **`use "a"` هو الذي فاز** — وهو أول تعريف في النص المدمج. ولو كان الترتيب
مقلوباً لفاز `b`. بالإضافة إلى الناتج يطبع المترجم الآن:

```text
Warning: redefinition of function 'helper' (first definition at line 1 wins; this one is at line 3, column 4)
```

لا يزال بإمكانك كتابة دالتين بنفس الاسم في ملفين والاعتماد على الترتيب،
لكن لم يعد ذلك صامتاً.

> **القاعدة العملية:** وحّد أسماء دوالك في كل الوحدات، أو استعمل بادئة مميزة
> لكل وحدة (`mathx_triple` بدل `triple`).

### 3) عمق التداخل: **32** لا 64

سلسلة `use` متداخلة (`a` يستورد `b` يستورد `c` ...) مسموحة حتى **عمق 32**. وبعدها
تفشل المعالجة المسبقة برسالة:

```text
Error: Maximum module nesting depth (32) exceeded while resolving 'use' chains
Error: Module preprocessing failed for 'main.mg'
```

> **تصحيح مهم:** الحد الأقصى **32** (سلسلة استيراد)، أما الرقم **64** فيخصّ عدد
> الوحدات المحمّلة لا عمق التداخل.

### 4) عدد الوحدات: 64

عند تجاوز 64 وحدة يوقف المترجم معالجة الوحدات برسالة واضحة بدلاً من تجاهلها:

```text
Error: Maximum loaded module count (64) exceeded
```

إن ظهرت لك `Undefined symbol` لدالة تعرف أنّها في `lib/`، فالأرجح أنك تجاوزت
الحدّ أو أن اسم الملف غير مطابق.

### 5) آثار جانبية على صياغة سطر `use`

سطر `use` يُقرأ نصياً، فتُعالَج قاعدته بقواعد بسيطة قد تفاجئك:

| ما تكتبه | ما يفهمه المترجم |
|-----------|------------------|
| `use "mathx";` | الوحدة `mathx` ✓ |
| `use mathx;` | الوحدة `mathx` ✓ |
| `use "./lib/mathx.mg";` | الوحدة `mathx` ✓ (تُنظَّف البادئة واللاحقة) |
| `use "mathx.fc";` | الوحدة `mathx` ✓ (لاحقة `.fc` تُنظَّف أيضاً) |
| `use std as s;` | الوحدة `std` ✓ (الجزء بعد `as` يُهمَل) |

صيغة `use x as y;` **تُحلّ الآن** باستيراد الوحدة `x`، لكن لا يوجد namespaces
حقيقية، لذا الاسم البديل `y` لا يعيد تسمية الرموز: استخدم أسماء الرموز الأصلية
بعد التضمين. لا يحدث خطأ `Could not find library module 'xasy'` بعد الآن.

### 6) مكان التضمين يهم

محتوى الوحدة يُدرج **في موضع سطر `use`**. فإن كان `use` في أول الملف، تسبق
تعريفات الوحدة تعريفات ملفك — ولهذا يفوز تعريف الوحدة عند التعارض.

أمّا وضع `use` **داخل جسم دالة** فيُفسد البرنامج: النص يُنسخ حرفياً داخل الدالة،
فيُترجَم الملف بنجاح لكنه **ينهار (SIGSEGV)** عند التشغيل.

ضع `use` دائماً في **أعلى الملف**، قبل أي دالة.

### 7) الوحدة المفقودة لا توقف الترجمة

إن لم يُعثر على الوحدة، يطبع المترجم تحذيراً ويُكمل:

```text
[Magnetar] Warning: Could not find library module 'mathx'
```

ثم تفشل الترجمة لاحقاً بـ `Undefined symbol` لكل دالة كان يوفّرها تلك الوحدة.
**اقرأ التحذير أولاً** — فهو سبب الخطأ الحقيقي.
