# 13 — التصحيح والسلوك غير المعرّف (Debugging)

> **TL;DR**
> - لا يوجد debugger: **لا stack traces ولا breakpoints ولا memory sanitizer** — التصحيح بالطباعة والتدقيق.
> - رسائل أخطاء النحو غنيّة (سطر وعمود ومؤشّر وToken)، ورسائل الربط مثل `Undefined symbol 'x'`.
> - `--watch` هو أسرع أداة تطوير: ترجمة وإعادة تشغيل عند كل حفظ.
> - أخطاء الذاكرة (خارج الحدود، تحرير مزدوج، use-after-free) كلها سلوك غير معرّف بلا إنذار.
> - صيد الأخطاء عملياً: اطبع المؤشرات، افحص `sizeof` قبل `alloc`، واستعمل `fixed`/`dyn` بدل `alloc`.

**حالة الدعم:** ✅ مستقر

---

## قراءة رسائل الأخطاء

رسائل Magnetar تأتي من ثلاث مراحل مختلفة، ولكل مرحلة شكلها الخاص — فتعرف من
شكل الرسالة **في أي مرحلة وقع الخطأ**.

### 1) أخطاء التحليل النحوي (Parser)

شكل الرسالة كاملاً:

```text
error: Expected ';' after print
  --> prog.mg:1:25
    1 | fn main() { print("hi") }
      |                         ^
  = token: '}'

✖ Compilation failed with 1 error.
```

الرسالة تعطيك أربعة أشياء: **ما** الخطأ، و**أين** (ملف:سطر:عمود)، وسطر
المصدر مع مؤشّر على العمود الذي أخطأ، و**الرمز** (`token`) الذي فاجأ المترجم.
هذا أغنى شكل خطأ في اللغة، استخدمه: اقرأ العمود أولاً، ثم عد إلى السطر.

### 2) أخطاء الربط (Backend / Linker)

```text
error: Undefined symbol 'nope'
[Magnetar] Code generation failed
```

تظهر بعد نجاح التحليل النحوي: الرمز **مُستدعى ولم يُعرَّف**. وهي الأسباب
العملية الشائعة:

- دالة مدمجة استعملتَها **بلا تصريح `extern fn`** (انظر [09_builtins.md](09_builtins.md)).
- اسم دالة غير موجود (خطأ مطبعي).
- دالة عضو (method) داخل `class`/`struct` استدعيتَها باسمها المجرّد بدل `this.<اسم>`.

> ⚠️ **ليس الخطأ هو الترتيب!** استدعاء دالة معرَّفة **بعد** نقطة الاستدعاء يعمل؛
> المترجم يجمع الرموز قبل التوليد. راجع
> [12_notes_and_limitations.md](12_notes_and_limitations.md#6-ترتيب-تعريف-الدوال-لا-يهم).

### 3) أخطاء سطر الأوامر (CLI)

```text
Error: Unknown option '--foo'
       Use --help for usage information.
```

### جدول أشهر 6 رسائل خطأ

| الرسالة | المرحلة | معناها | كيف تحلّها |
|---------|---------|--------|------------|
| `error: Expected ';' after ...` | Parser | جملة ناقصة الفاصلة المنقوطة | أضف `;` في العمود الذي يشير إليه المؤشّر |
| `error: Undefined symbol 'name'` | Backend | رمز مُستدعى غير معرَّف | أضف تصريح `extern fn` للدالة المدمجة، أو صحّح الاسم، أو استدعِ الـ method بـ `this.<اسم>` |
| `Error: Cannot open 'file.mg'` | CLI/IO | مسار الملف غير موجود | تحقّق من المسار ومن أن الملف في المجلد الحالي |
| `Error: Unknown option '--foo'` | CLI | خيار غير معروف | راجع [10_cli_reference.md](10_cli_reference.md) و `--help` |
| `Error: --target=baremetal is not implemented yet.` | CLI | هدف غير منفّذ | استخدم `x86_64` (أو `arm64`/`riscv` على مسؤوليتك) |
| `Error: Maximum module nesting depth (32) exceeded while resolving 'use' chains` | Preprocessing | سلسلة `use` أعمق من 32 | بسّط سلسلة الاستيراد، أو اكسر التداخل |

> **تحذير:** رسالة
> `[Magnetar] Warning: Could not find library module 'mathx'`
> **تحذير فقط ولا يوقف الترجمة**: الوحدة تُتجاهَل، فتظهر بعدها رسالة
> `Undefined symbol` لكل دالة كان يوفّرها. إن رأيت تحذيراً من هذا النوع فاتبعه
> فوراً بدل الانتظار حتى رسالة الربط.

### أخطاء لا يتوقف عندها المترجم (وهي الأخطر)

المترجم في v3.5 **لا يفحص الأنواع ولا الرموز إحصاءً كاملاً**، فبعض الأخطاء
البرمجية تمرّ الترجمة بسلامة ثم تفشل عند التشغيل:

```c
fn main() {
    print(x);            // x غير معرّفة: يُترجَم بنجاح ويطبع قيمة عشوائية من الذاكرة
}
```

```c
fn main() {
    int x = "text";      // نوع خاطئ: يُترجَم بنجاح
}
```

```c
fn foo() { }             // لا fn main: يُترجَم بنجاح، والبرنامج لا يفعل شيئاً
```

**القاعدة:** لا تثق في نجاح الترجمة دليلاً على صحة البرنامج؛ تحقّق من المخرجات.

## `--watch` كأداة تطوير

```bash
./magc prog.mg --watch
```

- يراقب وقت تعديل الملف كل ثانية.
- عند كل حفظ: يعيد الترجمة، ثم **يوقف النسخة القديمة** ويشغّل الجديدة.
- إذا فشلت الترجمة، تُطبع الرسالة ويبقى البرنامج القديم يعمل.
- للخروج: `Ctrl+C`.

**متى تستعمله؟**

- أثناء بناء خوارزمية: عدّل قيمة أو شرطاً واحفظ — يتحدّث الناتج فوراً.
- أثناء تصحيح طباعي: أضف `print` بين سطرين، احفظ، وشاهد المخرجات فوراً.
- عند مراجعة كود قديم: راقب ما يفعله كل تعديل على السلوك.

**متى لا تستعمله؟**

- حين يكون البرنامج طويل التشغيل (خادم أو حلقة لا نهائية): إعادة التشغيل المتكررة
  تُفسد الجلسة. استعمل `Ctrl+C` ثم تشغيلاً يدوياً.
- حين تحتاج نسخة نظيفة: `--watch` يبقي الإصدارات القديمة في الذاكرة.

> بديل عملي: `./magc prog.mg -o prog && ./prog` في سطر واحد، أو ضع الأمرين في
> دالة shell صغيرة.

## لا يوجد debugger

لغة Magnetar في v3.5 **لا توجد أدوات تصحيح**:

| الأداة | الحالة |
|--------|--------|
| Stack traces عند الانهيار | ❌ غير موجودة |
| انهيار المترجم نفسه (`magc`) | ✅ معالج `SIGSEGV` يطبع `SIGSEGV at rip=0x… rsp=0x… rbp=0x… addr=0x…` ثم يخرج بـ 139 |
| فهرسة خارج الحدود في البرنامج المُولَّد | ✅ اختيارياً عبر `magc --bounds-check` (وقت الترجمة، للمصفوفات `fixed` ذات الحجم الثابت) |
| Breakpoints / stepping | ❌ غير موجودة |
| Watchpoints / inspection | ❌ غير موجودة |
| Memory sanitizer (ASan) | ❌ غير موجودة |
| Memory leak detector | ❌ غير موجودة |

> **الحد الأدنى المتاح:** `magc` يثبّت معالج `SIGSEGV` يطبع مؤشر التعليمة ومؤشري
> المكدس والإطار وعنوان الخطأ عند انهيار **المترجم**، وأمّا البرامج المولَّدة
> فهي بلا libc، لذا لا يمكنها طباعة stack trace؛ بدلاً من ذلك يوفّر
> `--bounds-check` رفضاً وقت الترجمة للفهارس الحرفية المعروف تجاوزها لحدود
> `fixed<T,N>`، برسالة تحتوي السطر والعمود. الفهارس الديناميكية لا تُرفض لأن
> حدودها غير معروفة وقت الترجمة.

**ماذا يعني هذا عملياً؟**

- عند `Segmentation fault` لا تحصل على سطر الدالة ولا قائمة دوال — فقط كود
  الخروج `139`.
- لا يمكنك إيقاف البرنامج عند نقطة بعينها؛ التصحيح يتم **بالطباعة** وبتقطيع
  البرنامج.
- لا أداة تكشف لك كتابة خارج حدود مصفوفة؛ فحص الحدود يدوي بالكامل.

**البديل العملي — ثلاث تقنيات:**

1. **الطباعة الاستقصائية:** اطبع القيم عند كل نقطة يشك فيها:

   ```c
   print("i="); print(i); print(" acc="); print(acc); print("\n");
   ```

2. **التصغير التدريجي (bisect):** احذف نصف أجزاء البرنامج وراجع الخرج؛ إن اختفى
   الخطأ فالجزء المحذوف فيه السبب.

3. **الحارس اليدوي:** ضع فحصاً صريحاً قبل كل عملية حساسة:

   ```c
   extern fn exit(int code) -> void;

   fn main() {
       if (i < 0 || i >= n) {
           print("index out of range\n");
           exit(1);
       }
   }
   ```

   > `exit` دالة مدمجة تحتاج تصريح `extern fn` في أعلى الملف — راجع
   > [09_builtins.md](09_builtins.md).

## كيف تصطاد أخطاء الذاكرة

### 1) اطبع المؤشرات وقيمها

القيم عشوائية بعد خطأ في الحساب، أما المؤشرات فتخبرك أين تذهب:

```c
print("ptr="); print(p); print("\n");
print("val="); print(*p); print("\n");
```

إذا كان `ptr` سالباً أو صفراً، فالمشكلة في الحساب لا في الكتابة.

### 2) افحص `sizeof` قبل `alloc`

`sizeof` تخبرك بعرض النوع، و`alloc` تخبرك بخطوة الحجز:

```c
print(sizeof(int));    // 8
print(sizeof(float));  // 4
print(sizeof(char));   // 1
```

> المصفوفة `fixed` تحجز 8 بايت لكل عنصر؛ `sizeof(fixed<T,N>)` يعيد الحجم الكامل
> للمصفوفة، بينما `sizeof(T)` يعيد الحجم المنطقي للعنصر.
> (انظر [المرجع الموحّد](07_pointers_arrays_memory.md#المرجع-الموحّد-alloctn)).

### 3) استعمل `fixed`/`dyn` بدل `alloc` متى أمكن

```c
fixed<int, 4> a = {1, 2, 3, 4};   // الطول معلوم: أخطاء الفهرسة أخطاء منطق صريحة
dyn<int> d = {1, 2, 3};            // الطول من المُهيِّئ
```

الفارق: مع `fixed`/`dyn` يصبح خطؤك **خطأ منطق** تراه بعينك، ومع `alloc` يصبح
**كتابة في مكان مجهول**.

### 4) أضف فحوصات يدوية قبل كل فهرسة

```c
if (i >= 0 && i < 4) {
    print(a[i]);
}
```

ولا تنسَ: `alloc` لا يُصفّر الذاكرة. أول خطأ شائع هو قراءة خانة لم تكتبها.

### 5) حرّر مرة واحدة فقط

احتفظ بمتغيّر منطقي لكل تخصيص، ولا تمرّر `free` بالمؤشر نفسه مرتين.

## سلوك غير معرّف (Undefined Behavior)

الجدول أدناه يلخّص ما يحدث **فعلاً** في v3.5 (مقيساً بالتشغيل على Linux x86_64):

| السلوك | النتيجة |
|--------|---------|
| قراءة خارج حدود `fixed` | سلوك غير معرّف — **لا ينهار**، بل يقرأ ذاكرة عشوائية بصمت (وقد يطبع قيمة منطقية كـ `0`) |
| تحرير مؤشر مرتين | سلوك غير معرّف — **SIGSEGV** (core dumped) في v3.5 لأن الحجم يُقرأ من ذاكرة محرَّرة |
| استخدام مؤشر بعد `free` | سلوك غير معرّف — **SIGSEGV** (core dumped) في v3.5، لأن الصفحة محرَّرة من خريطة العملية |
| قسمة أعداد صحيحة على صفر | رسالة `magnetar: division by zero` على stderr، ثم خروج بالكود `1` |
| قسمة أعداد عشرية على صفر | لا تنهار، لكن النتيجة **قيمة عشوائية** (في v3.5 تطبع `-9223372036854775808`) |

> **القاعدة الذهبية:** كل ما في هذا الجدول **سلوك غير معرّف** من ناحية اللغة.
> أي سلوك رأيته اليوم (رقم عشوائي، أو انهيار متأخر في مكان آخر) قد يتغيّر غداً
> بعد أي تحديث للمترجم.

### كيف تقرأ كود الخروج

| الكود | المعنى |
|-------|--------|
| `0` | خروج طبيعي (عند `fn main() -> int { return 0; }`) |
| `1` أو أي رقم آخر | خروج طبيعي بغير `return` صريح — القيمة هي ما تبقّى في السجل، **غير مضمونة** (لاحظنا 1 و3 و8 و14) |
| `136` | `SIGFPE` — قسمة على صفر بين أعداد صحيحة |
| `139` | `SIGSEGV` — مؤشر حرّأ أو مستخدم بعد `free`، أو خطأ فهرسة كبير |

> **ملاحظة مهمة:** البرنامج الذي ينتهي طبيعياً **لا يعيد بالضرورة 0**؛ فـ
> `fn main()` بلا نوع إرجاع تُعيد ما تبقّى في السجل. إن أردت كود خروج موثوقاً
> فاكتب `fn main() -> int { return 0; }` أو استخدم `exit(0)` (مع تصريح
> `extern fn exit(int code) -> void;`).

---

## ماذا تفعل حين ينهار البرنامج؟

1. **حدّد نوع الانهيار من كود الخروج:** `139` = SIGSEGV (ذاكرة)، `136` = SIGFPE
   (قسمة على صفر).
2. **أضف طباعة عند آخر نقطة تعرف أنها سليمة**، ثم أعد الترجمة — قِس المسافة
   بين آخر طباعة سليمة وأول طباعة غائبة.
3. **راجع كل فهرسة** في ذلك المدى: قسمة على صفر، فهرسة خارج الحدود، تحرير
   مزدوج، أو pointer مُعاد إلى دالة انتهت (`free` محلي).
4. **أعد بناء الكود بالتدريج**: استبدل كل `alloc` بـ `fixed` مؤقتاً — إن اختفى
   الانهيار فالمشكلة في الذاكرة المُدارة يدوياً.
